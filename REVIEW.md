# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `parse_epoch_ms` / ln 24-28 | Used local naive time conversion without enforcing UTC epoch parsing and whole-second normalization. | Tests across different local server timezones yield different punch times; fractional milliseconds were not truncated. | Converted epoch to seconds (`ms / 1000.0`), created timezone-aware UTC datetime, and truncated milliseconds to whole seconds per R1. |
| 2 | `calc_attendance_date` / ln 31-35 | Calendar date was naively extracted using `strftime("%Y-%m-%d")` without handling overnight shifts spanning past midnight (R1). | A punch-in at 00:30 IST for an overnight shift (22:00 - 06:00) gets assigned to the new calendar day instead of the shift's starting date. | Implemented overnight shift detection (`shift_end < shift_start`); if punch occurs after midnight but before `shift_end`, date maps to the previous day. |
| 3 | `calc_late_minutes` / ln 38-45 | Calculated time difference without applying the 10-minute grace window and floor-to-minute rounding rule (R2). | Punch at 09:40:00 was counted as 10 min late instead of 0 min; 09:40:01 was not properly floored to 10 min. | Applied R2 logic: if arrival <= shift_start + 10 min, late = 0; otherwise `math.floor((punch_time - shift_start).total_seconds() / 60)`. |
| 4 | `calc_work_hours` / ln 48-52 | Used standard Python `round()` (banker's rounding) and floating point division instead of ROUND_HALF_UP (R4). | Edge cases ending in `.x5` round to the nearest even number rather than rounding up to 2 decimal places. | Used `decimal.Decimal` with `ROUND_HALF_UP` to round total hours to 2 decimal places deterministically. |
| 5 | `calc_overtime` / ln 55-60 | Counted all extra minutes as overtime regardless of the 30-minute threshold requirement (R5). | Working 15 minutes beyond shift was counted as 15 minutes overtime instead of 0 minutes. | Enforced strict R5 rule: overtime is 0 if extra time < 30 minutes; if >= 30 minutes, full difference is recorded. |
| 6 | `create_employee` / ln 75-85 | Relied on application-level `find_one` before insert; vulnerable to race conditions and missing unique index. | Concurrent `POST /employees` with identical `emp_code` both succeed, creating duplicate employee records. | Created unique index on `emp_code` and handled `DuplicateKeyError` to return 409 Conflict. Validated `shift_start != shift_end`. |
| 7 | `punch_in` / ln 92-108 | Used non-atomic `find_one` followed by `insert_one` without concurrency protection. | Simultaneous double punch-in requests both pass the check and create duplicate daily attendance documents. | Backed by unique compound index on `{emp_code: 1, date: 1}` and caught `DuplicateKeyError` to return 409 Conflict. |
| 8 | `punch_out` / ln 115-132 | Performed non-atomic check and update; allowed multiple punch-out calls and race condition overwrite. | Concurrent punch-out calls both succeed or overwrite computed hours; punching out without punch-in returned unhandled errors. | Used atomic `find_one_and_update` filtering on `punch_out: None` and `punch_in: {"$ne": None}`; returns 409 if already punched out or not punched in. |
| 9 | `patch_attendance` / ln 140-165 | Failed to maintain immutable audit trail in `history` array; did not reset derived metrics when status changed to ABSENT/LEAVE. | Changing status to ABSENT left stale `work_hours` and `late_minutes`; no history of who changed what or when. | Added atomic `$push` of audit entry (`at`, `by`, `reason`, `changes` diff map) and cleared punch times/metrics when regularizing to ABSENT/LEAVE. |
| 10 | Analytics endpoints / ln 170-220 | Executed queries by loading raw records into Python memory and aggregating using loops and list comprehensions. | Severe memory exhaustion and high latency at scale; violates assignment requirement for MongoDB aggregation pipelines. | Replaced all analytics endpoints with pure MongoDB aggregation pipelines (`$match`, `$group`, `$densify`, `$setWindowFields`, `$rank`, `$lookup`). |
| 11 | Startup lifecycle / ln 15-20 | Missing index creation on application startup; left database unindexed and explain plans unoptimized. | `/admin/explain` queries defaulted to `COLLSCAN` with high `docsExamined` counts. | Added `@app.on_event("startup")` index creation for all primary query patterns idempotently. |

### Considered and Decided NOT a Defect:
- **Excluding Weekends for `working_days`:** We evaluated whether gazetted public holidays should be factored into working days for monthly analytics. In R7 and the OpenAPI contract, working days are explicitly defined as Monday through Friday within the month (`[d for d in month_days if d.weekday() < 5]`). Keeping this strictly Monday–Friday conforms to the contract.
- **Single active shift assumption:** The assignment model assumes one scheduled shift per employee per day rather than rotating shifts within the same day. Given the schema and problem definition, treating `shift_start` and `shift_end` on the employee document as authoritative is correct.
